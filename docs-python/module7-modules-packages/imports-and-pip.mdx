# 7.1 الوحدات (Modules) ومدير الحزم (Pip)

تخيل أن كودك أصبح يتكون من 2000 سطر، هل ستتركه كله في ملف واحد `main.py`؟ بالطبع لا.
في بايثون، نستخدم ما يسمى بالـ **Modules** (الوحدات) لتقسيم الكود لعدة ملفات، ونستخدم أداة **Pip** لتحميل أكواد كتبها مبرمجون آخرون حول العالم لتسهيل حياتنا!

---

## 1. استيراد المكتبات المدمجة (Built-in Modules)

بايثون تأتي مع "بطاريات مشحونة" (Batteries Included). هذا يعني أن لديها مكتبات ضخمة مدمجة فيها لا تحتاج لأي تحميل، يكفي فقط أن تستدعيها بكلمة `import`.

```python
# 1. استدعاء مكتبة كاملة
import math

print(math.sqrt(16)) # 4.0
print(math.pi)       # 3.1415...

# 2. استدعاء دالة محددة فقط (لتوفير الذاكرة وتسهيل الكتابة)
from random import randint, choice

print(randint(1, 10)) # رقم عشوائي بين 1 و 10
print(choice(["Apple", "Banana", "Mango"])) # اختيار عشوائي من القائمة

# 3. إعطاء اسم مستعار (Alias)
import datetime as dt

now = dt.datetime.now()
print(now.year)
```

---

## 2. إنشاء Module خاص بك

الموديول في بايثون هو مجرد ملف بايثون عادي `.py`. يمكنك كتابة دوالك في ملف، واستدعاؤها في ملف آخر.

**ملف: `calculator.py`**
```python
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b
```

**ملف: `main.py` (في نفس المجلد)**
```python
# نقوم باستدعاء الملف باسمه (بدون .py)
import calculator

result = calculator.add(5, 10)
print(result) # 15

# أو استدعاء الدالة مباشرة
from calculator import multiply
print(multiply(4, 3)) # 12
```

---

## 3. السطر السحري: `if __name__ == "__main__":`

في بعض الأحيان تكتب كوداً لاختبار دوالك داخل `calculator.py`. المشكلة أنه عندما تقوم بعمل `import calculator` في `main.py`، سيتم تشغيل كود الاختبار هذا تلقائياً! 

لمنع ذلك، نضع أكواد التشغيل داخل هذا الشرط السحري. هذا الشرط يعني: **"نفذ هذا الكود فقط إذا تم تشغيل هذا الملف مباشرة، وتجاهله إذا تم استدعاء الملف كـ Module"**.

```python
# calculator.py
def add(a, b):
    return a + b

# سيتم تجاهل هذا الجزء عند الاستدعاء (import) من ملف آخر
if __name__ == "__main__":
    print("Testing calculator...")
    print(add(2, 2))
```

## 4. تحميل مكتبات خارجية باستخدام (Pip)

بايثون تمتلك أضخم مجتمع مطورين في العالم، وهؤلاء المطورون يرفعون أكوادهم الجاهزة على الإنترنت لكي تستخدمها.
لتحميل هذه الأكواد، نستخدم مدير الحزم الخاص ببايثون والذي يُسمى **`pip`** (وهو يُثبت تلقائياً مع بايثون).

لتحميل مكتبة (مثلاً مكتبة `requests` الشهيرة لجلب البيانات من الإنترنت):
افتح הـ **Terminal** أو موجه الأوامر واكتب:
```bash
pip install requests
```

بعد انتهاء التحميل، يمكنك استخدامها فوراً في كودك:
```python
import requests

# جلب بيانات من موقع وهمي
response = requests.get("https://jsonplaceholder.typicode.com/todos/1")
print(response.json()) 
```

### أوامر Pip الهامة (في הـ Terminal):
- `pip install <package_name>`: لتحميل حزمة.
- `pip uninstall <package_name>`: لمسح حزمة.
- `pip list`: لعرض كل الحزم المثبتة على جهازك.

## ⚡ Performance Notes

:::tip خرافة توفير الذاكرة عند استخدام `from x import y`
يعتقد الكثيرون أن استخدام `from math import sqrt` يستهلك ذاكرة أقل من استيراد المكتبة كاملة `import math`. **هذه خرافة!** في كلتا الحالتين، تقوم بايثون بتحميل كامل الموديول في الذاكرة خلف الكواليس وتخزنه في `sys.modules`. الفرق الوحيد هو في "الاسم" الذي يتاح لك استخدامه.
**نصيحة الأداء الحقيقية (Lazy Imports):** إذا كان لديك موديول ضخم جداً ولن تحتاجه إلا في دالة واحدة نادراً ما تُستخدم، قم بكتابة أمر الـ `import` داخل تلك الدالة نفسها! هكذا لن يتم تحميله في الذاكرة إلا إذا تم استدعاء الدالة فعلياً مما يسرّع بدء البرنامج.
:::

## ⚠️ الأخطاء الشائعة (Common Mistakes)

```python
# ❌ 1 - الاستيراد الدائري (Circular Imports)
# تخيل أنك في ملف A.py وتكتب: import B
# وفي نفس الوقت داخل ملف B.py تكتب: import A
# 💥 خطأ: ImportError! سيدخل البرنامج في حلقة مفرغة وتفشل عملية الاستيراد.
# ✅ الحل: أعد تصميم الكود لتجنب الاعتماد المتبادل، أو استخدم الـ Lazy Import بوضع الاستدعاء داخل الدالة وليس في أعلى الملف.

# ❌ 2 - تسمية ملفك بنفس اسم مكتبة مدمجة
# إذا أنشأت ملفاً باسم math.py ثم كتبت بداخله import math.
# 💥 خطأ: بايثون ستقرأ ملفك أنت ولن تجد داخله دوال مكتبة الـ math الأصلية (Shadowing). 
# ✅ الحل: اختر أسماء فريدة لملفاتك ولا تسميها بأسماء مكتبات شهيرة.
```

## Interview Questions & Answers

<details>
<summary><strong>Q1: ماذا تفعل علامة النجمة في `from module import *`؟ ولماذا لا يُنصح بها؟</strong></summary>

تقوم باستيراد **كل الدوال والمتغيرات** من هذا الموديول إلى كودك الحالي، بحيث يمكنك كتابتها مباشرة بدون اسم الموديول قبلها. 
لا يُنصح بها إطلاقاً (إلا للتجربة) لأنها تسبب تلوثاً لبيئة الأسماء (Namespace Pollution). إذا كان لديك دالة اسمها `calculate()` واستوردت مكتبة باستخدام `*` تحتوي على دالة بنفس الاسم، سيحدث تضارب وتتغير وظيفة دالتك الأصلية دون أن تدري.
</details>

<details>
<summary><strong>Q2: أين يقوم `pip` بتثبيت المكتبات التي أحملها؟</strong></summary>

بشكل افتراضي، يقوم `pip` بتثبيتها عالمياً (Globally) في المجلد الذي تم تثبيت بايثون فيه على جهازك. هذا يعني أن كل مشاريعك ستشارك نفس المكتبة ونفس الإصدار. هذه الطريقة تسبب مشاكل (Dependency Conflicts) وسنتعلم حلها في الدرس القادم عبر הـ Virtual Environments.
</details>

<SummaryBox title="📌 Lesson Summary">

- **Modules** هي مجرد ملفات `.py` تحتوي على أكواد، نستدعيها لتقسيم الكود وتسهيل إدارته.
- نستخدم الكلمات **`import`** و **`from`** لجلب الدوال.
- السطر **`if __name__ == "__main__":`** يحمي الأكواد من التشغيل العشوائي عند الاستدعاء.
- أداة **`pip`** (في سطر الأوامر) هي البوابة السحرية لتحميل آلاف المكتبات الجاهزة عالمياً.

</SummaryBox>
