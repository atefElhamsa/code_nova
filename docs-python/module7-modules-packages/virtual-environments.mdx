# 7.2 البيئات الوهمية (Virtual Environments)

تخيل أنك تعمل على مشروعين:
- **المشروع الأول (تطبيق ويب):** يحتاج لمكتبة Django الإصدار 2.
- **المشروع الثاني (تطبيق جديد):** يحتاج لمكتبة Django الإصدار 4.

إذا استخدمت `pip install django` بالطريقة العادية، سيتم تثبيت الإصدار عالمياً (Globally) على جهازك بالكامل! لا يمكنك تثبيت إصدارين مختلفين من نفس المكتبة في نفس المكان. هذا سيؤدي إلى كسر أحد المشروعين (Dependency Hell).
لحل هذه الكارثة، ابتكرت بايثون ما يسمى بـ **البيئات الوهمية (Virtual Environments)**.

---

## 1. ما هي البيئة الوهمية (venv)؟

البيئة الوهمية هي ببساطة **مجلد (Folder)** يتم إنشاؤه داخل مشروعك. هذا المجلد يحتوي على نسخة معزولة ومستقلة من مفسر بايثون (Python Interpreter) ومن أداة `pip`. 
عندما "تُفعل" هذه البيئة، فإن أي مكتبة تحملها بـ `pip` سيتم تثبيتها داخل هذا المجلد فقط، ولن تؤثر على باقي الجهاز أو المشاريع الأخرى.

---

## 2. إنشاء وتفعيل البيئة الوهمية

هذه الخطوات يجب أن تقوم بها في الـ Terminal في بداية أي مشروع جديد (وهي من أساسيات العمل كمطور بايثون محترف).

### الخطوة الأولى: الإنشاء
افتح الـ Terminal (داخل مجلد مشروعك) واكتب:
```bash
python -m venv myenv
# "myenv" هو اسم المجلد، يمكنك تسميته venv أو .venv
```
ستلاحظ ظهور مجلد جديد في مشروعك باسم `myenv`. (لا تقم بتعديل أي شيء داخله يدوياً).

### الخطوة الثانية: التفعيل (Activation)
يجب أن تخبر نظام التشغيل أن يستخدم هذه البيئة المعزولة.
- **في الويندوز (Command Prompt):**
  ```bash
  myenv\Scripts\activate
  ```
- **في الويندوز (PowerShell) أو (Mac/Linux):**
  ```bash
  source myenv/bin/activate
  ```

✅ **علامة النجاح:** ستلاحظ ظهور اسم البيئة بين قوسين `(myenv)` في بداية سطر الأوامر. الآن أنت في الوضع الآمن! أي شيء تحمله الآن سيكون معزولاً.

### الخطوة الثالثة: إيقاف التفعيل (Deactivation)
إذا انتهيت من العمل وأردت الخروج من البيئة، اكتب ببساطة:
```bash
deactivate
```

---

## 3. حفظ الحزم المطلوبة (requirements.txt)

عندما تشارك مشروعك مع مبرمج آخر (أو ترفعه على GitHub)، فإنك **لا** ترفع مجلد الـ `myenv` لأنه ثقيل جداً ويختلف من نظام تشغيل لآخر.
بدلاً من ذلك، أنت تولّد ملفاً نصياً صغيراً يحتوي على "قائمة بكل المكتبات وإصداراتها" التي استخدمتها في هذا المشروع.

### توليد الملف:
وأنت داخل البيئة المُفعلة، اكتب:
```bash
pip freeze > requirements.txt
```
هذا سينشئ ملف `requirements.txt` في مشروعك.

### تثبيت الحزم (إذا كنت المبرمج الآخر):
عندما يأخذ مبرمج آخر مشروعك، سيقوم بإنشاء بيئة وهمية خاصة به، ثم سيكتب:
```bash
pip install -r requirements.txt
```
وسيقوم `pip` آلياً بتحميل كل المكتبات بالإصدارات المطابقة تماماً لبيئتك ليعمل المشروع بنجاح 100%.

## ⚡ Performance Notes

:::tip حجم البيئة الافتراضية والـ CI/CD
البيئة الافتراضية (venv) بحد ذاتها لا تبطئ سرعة تنفيذ كود بايثون إطلاقاً. ولكن، تراكم المكتبات غير المستخدمة داخل البيئة يؤدي إلى ملف `requirements.txt` ضخم جداً. 
هذا يسبب **بطئاً كارثياً** في عمليات النشر الآلي (CI/CD) على السيرفرات، حيث يستغرق الخادم وقتاً طويلاً في تحميل وتثبيت مكتبات أنت لا تحتاجها أساساً! حافظ دائماً على بيئتك نظيفة ومقتصرة على ما تحتاجه فقط.
:::

## ⚠️ الأخطاء الشائعة (Common Mistakes)

```bash
# ❌ 1 - رفع مجلد البيئة الوهمية venv إلى GitHub
# 💥 كارثة! هذا المجلد قد يكون حجمه مئات الميجابايتات، ويحتوي على ملفات تعمل على نظام تشغيلك أنت فقط ولن تعمل عند صديقك.
# ✅ الحل الدائم: فور إنشاء المشروع، أنشئ ملف .gitignore واكتب بداخله venv/ لكي يتجاهله Git تماماً.

# ❌ 2 - تثبيت المكتبات قبل تفعيل البيئة
# pip install django
# 💥 إذا نسيت تفعيل البيئة (activate) ونفذت الأمر، سيتم التثبيت على جهازك بالكامل (Globally) وستفقد ميزة العزل!
# ✅ الحل: تأكد دائماً من وجود اسم البيئة (venv) بجوار سطر الأوامر قبل كتابة أي أمر pip.
```

## Interview Questions & Answers

<details>
<summary><strong>Q1: هل الـ Virtual Environment يحتوي على نظام تشغيل وهمي (مثل Docker أو VirtualBox)؟</strong></summary>

لا. الـ Virtual Environment في بايثون ليست أداة (Virtualization) لنظام التشغيل. هي مجرد "خدعة مسارات" (Path Manipulation). عند تفعيلها، تقوم بايثون بتغيير المسار الافتراضي للـ `pip` والـ `python` ليشير إلى المجلد المحلي الخاص بمشروعك بدلاً من المجلد العام في نظام التشغيل.
</details>

<details>
<summary><strong>Q2: أواجه خطأ في الويندوز (PowerShell) يقول "execution of scripts is disabled" عند محاولة تفعيل البيئة؟</strong></summary>

هذا الخطأ شائع جداً لأن ويندوز يمنع تشغيل السكريبتات بشكل افتراضي كإجراء أمني.
لحل المشكلة نهائياً، افتح PowerShell كمسؤول (Run as Administrator) واكتب هذا الأمر:
`Set-ExecutionPolicy Unrestricted -Force`
ثم جرب التفعيل مرة أخرى.
</details>

هذا تمرين للـ Terminal وليس لكتابة كود بايثون:
1. أنشئ مجلداً جديداً على جهازك باسم `my_app`.
2. افتح الـ Terminal داخل هذا المجلد.
3. أنشئ بيئة وهمية باسم `venv`.
4. قم بتفعيلها.
5. تأكد من التفعيل بتثبيت مكتبة (مثلاً `pip install requests`).
6. قم بتوليد ملف `requirements.txt`.

</ExerciseBox>

<details>

```bash
# 1 & 2. (افتح الـ Terminal في مسار المجلد الجديد)

# 3. الإنشاء

# 4. التفعيل (مثال ويندوز CMD)
venv\Scripts\activate
# (تأكد من ظهور كلمة (venv) قبل السطر)

# 5. تثبيت حزمة للاختبار
pip install requests

# 6. توليد ملف الحزم

```

<SummaryBox title="📌 Lesson Summary">

- الـ **Virtual Environment** (venv) هي بيئة معزولة لتثبيت مكتبات كل مشروع بشكل مستقل ومنع التعارض.
- للإنشاء: `python -m venv env_name`
- للتفعيل (ويندوز): `env_name\Scripts\activate` وللإيقاف: `deactivate`
- لإنشاء قائمة بالمكتبات المُستخدمة: `pip freeze > requirements.txt`
- لتثبيت القائمة بضغطة زر: `pip install -r requirements.txt`

</SummaryBox>
