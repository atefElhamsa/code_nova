# 4.5 إدارة حالات الواجهة الاحترافية (UI State Handling)

تتعرض شاشات التطبيق لعدة حالات حتمية: التحميل، النجاح بالبيانات، الفشل برسالة خطأ، أو القائمة الفارغة.

---

## 🎯 أهداف الدرس (Learning Objectives)

1. تعريف التعداد ViewStatus لحالات الواجهة.
2. بناء شاشات تفاعلية تستجيب لكل حالة بـ Switch Expression.
3. إدارة أزرار إعادة المحاولة (Retry Mechanism).

---

## 1. تعداد حالات الواجهة (ViewStatus Enum)

### 📘 الشرح النظري
نعرف Enum يحتوي على كافة الحالات المتوقعة للشاشة لمنع الاستخدام المربك للـ booleans المتعددة.

### 💻 التطبيق العملي
```dart
enum ViewStatus { initial, loading, success, failure, empty }
```

---

## 2. استجابة الواجهة لحالات الـ ViewModel

### 📘 الشرح النظري
نستخدم تعبير `switch` داخل طريقة `build` لعرض الودجة المناسبة لكل حالة بنظافة تامة.

### 💻 التطبيق العملي
```dart
Widget buildStateUI(ViewStatus status) {
  return switch (status) {
    ViewStatus.loading => const CircularProgressIndicator(),
    ViewStatus.failure => const Text('حدث خطأ بالشبكة!'),
    ViewStatus.empty   => const Text('لا توجد بيانات'),
    ViewStatus.success => const Text('تم جلب البيانات بنجاح!'),
    _                  => const SizedBox(),
  };
}
```

---

## ⚡ نصائح الأداء والتحسين (Performance Tips)

:::tip الشمول التام للحالات
استخدام `switch` يضمن لك عدم نسيان عرض مؤشر التحميل أو رسالة الخطأ للمستخدم.
:::

---

## 🐛 أخطاء شائعة يجب تجنبها (Common Mistakes)

```dart
// ❌ 1. استخدام متقاطعات بولينية متعددة مثل isLoading & isError
if (isLoading) ... else if (isError) ... // 💥 حالة ارتباك متقاطعة

// ✅ الحل الصحيح
switch (viewModel.status) { ... } // ✅ حالة محددة ناصعة

```
