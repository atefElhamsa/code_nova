# 4.5 التعامل مع حالات واجهة المستخدم (State Handling: Loading, Error, Success)

تعتبر التغذية البصرية الواضحة أساس تجربة المستخدم الناجحة (UX). ينبغي للواجهة أن تعكس الحالة الحالية للتطبيق بدقة متناهية: هل نحن في حالة **تحميل (Loading)**، أو **نجاح (Success)**، أو **فشل (Failure)**، أو **قائمة فارغة (Empty)**.

---

## 🎯 أهداف الدرس (Learning Objectives)

1. إدار حالات الواجهة باستخدام نمط الحالات المعمم `ViewState<T>` أو `Enum`.
2. تصميم واجهة تكيفية تبني الودجة المناسبة بناءً على حالة الـ ViewModel.
3. التخلص من التعقيدات والشروط المكررة في الـ Widgets.
4. توفير إمكانية إعادة المحاولة (Retry Mechanism) بنظافة عند حدوث الأخطاء الشبكية.

---

## 📘 الشرح النظري (Theoretical Explanation)

بدلاً من استخدام عدة متغيرات بوليانية متفرقة مثل `bool isLoading`, `bool isError`, `bool isSuccess` (مما قد يوقع التطبيق في حالات متناقضة كـ `isLoading = true` و `isSuccess = true` في نفس الوقت)، نقوم بتجميع الحالات في نمط حالة موحد صريح (Exhaustive Enum State).

```dart
enum ViewStatus { initial, loading, success, failure, empty }
```

---

## 💻 التطبيق المعماري (MVVM & Clean Code)

بناء ViewModel شمول يطبق نمط الحالات الموحد مع واجهة تتفاعل بسلاسة مع كل حالة.

```dart
// ==========================================
// File: lib/core/enums/view_status.dart
// Description: حالات الواجهة العامة الموحدة
// Architecture Layer: Core Enums
// ==========================================

enum ViewStatus { initial, loading, success, failure, empty }

// ==========================================
// File: lib/presentation/viewmodels/article_list_viewmodel.dart
// Description: ViewModel يتولى تغيير حالات ViewStatus بنظافة
// Architecture Layer: Presentation (ViewModel)
// ==========================================

import 'package:flutter/foundation.dart';
import '../../core/enums/view_status.dart';

class ArticleListViewModel extends ChangeNotifier {
  ViewStatus _status = ViewStatus.initial;
  List<String> _articles = [];
  String _errorMessage = '';

  ViewStatus get status => _status;
  List<String> get articles => _articles;
  String get errorMessage => _errorMessage;

  Future<void> fetchArticles() async {
    _status = ViewStatus.loading;
    notifyListeners();

    try {
      await Future.delayed(const Duration(seconds: 1));
      
      // محاكاة استلام قائمة ناجحة
      final fetchedData = ['الدرس الأول: Dart', 'الدرس الثاني: Flutter'];

      if (fetchedData.isEmpty) {
        _status = ViewStatus.empty;
      } else {
        _articles = fetchedData;
        _status = ViewStatus.success;
      }
    } catch (e) {
      _errorMessage = 'تعذر الاتصال بالخادم. يرجى التأكد من الإنترنت.';
      _status = ViewStatus.failure;
    } finally {
      notifyListeners();
    }
  }
}
```

<ExerciseBox title="جرب بنفسك 💻">

1. أنشئ ودجة الشاشة التي تستمع لـ `ArticleListViewModel`.
2. استخدم تعبير `switch (viewModel.status)` لبناء:
   - `ViewStatus.loading` -> `CircularProgressIndicator()`
   - `ViewStatus.failure` -> نص الخطأ مع زر `ElevatedButton` لإعادة المحاولة.
   - `ViewStatus.empty` -> رسمة أو نص "لا توجد بيانات".
   - `ViewStatus.success` -> `ListView.builder`.

</ExerciseBox>

---

<SummaryBox title="خلاصة الدرس 📌">

- استخدام `ViewStatus` الصريح يضمن حماية الواجهة من الوصول إلى حالات متناقضة غير منطقية.
- توفير زر إعادة المحاولة (Retry) في حالة الفشل يعتبر من أهم معايير جودة التطبيقات.
- تظل الـ View بسيطة جداً وتقوم فقط بمطابقة حالة `ViewStatus` بالودجة المناسبة لها.

</SummaryBox>
