# 2.2 شجرة الودجات وشجرة العناصر (Widget & Element Tree)

تعتمد لغة Flutter على ثلاث أشجار رئيسية في معالجة الرسوميات: **Widget Tree**, **Element Tree**, و **RenderObject Tree**. فهم العلاقة بين هذه الأشجار هو المفتاح الأساسي لكتابة أداء عالي وسلس بـ 60/120 إطاراً في الثانية.

---

## 🎯 أهداف الدرس (Learning Objectives)

1. التمييز بين StatelessWidget و StatefulWidget.
2. فهم دور شجرة العناصر (Element Tree) كوسطاء إدارة الحالة.
3. استيعاب دورة حياة الـ State (initState, didChangeDependencies, build, dispose).

---

## 1. الودجات غير ذات الحالة (StatelessWidget)

### 📘 الشرح النظري
تُعتبر `StatelessWidget` ودجة غير ثنائية الحالة (Immutable)، تُستخدم لعرض بيانات ثابتة لا تتغير مع مرور الوقت بناءً على المدخلات التي تستقبلها في البناء.

### 💻 التطبيق العملي
```dart
import 'package:flutter/material.dart';

class UserHeaderWidget extends StatelessWidget {
  final String userName;
  const UserHeaderWidget({super.key, required this.userName});

  @override
  Widget build(BuildContext context) {
    // ودجة خفيفة غير ثنائية القيمة تُبنى بسرعة عالية
    return Text('Welcome back, $userName!', style: const TextStyle(fontSize: 18));
  }
}
```

## 2. الودجات ذات الحالة ودورة الحياة (StatefulWidget Lifecycle)

### 📘 الشرح النظري
تُستخدم `StatefulWidget` عندما تتغير بيانات الشاشة أثناء تشغيل التطبيق (مثل العدادات والتنقلات). ترتبط هذه الودجة بكائن `State` يُدار في شجرة العناصر (`Element Tree`).

### 💻 التطبيق العملي
```dart
class CounterWidget extends StatefulWidget {
  const CounterWidget({super.key});

  @override
  State<CounterWidget> createState() => _CounterWidgetState();
}

class _CounterWidgetState extends State<CounterWidget> {
  int _count = 0;

  @override
  void initState() {
    super.initState();
    // 1. يُستدعى مرة واحدة فقط عند إنشاء الـ Element في الشجرة
    print('initState: Component mounted.');
  }

  void _increment() {
    // 2. setState تُعلم الـ Element Tree بإعادة استدعاء build()
    setState(() => _count++);
  }

  @override
  Widget build(BuildContext context) {
    return ElevatedButton(
      onPressed: _increment,
      child: Text('Count: $_count'),
    );
  }

  @override
  void dispose() {
    // 3. يُستدعى عند حذف الودجة نهائياً وتنظيف الذاكرة
    print('dispose: Cleaning memory.');
    super.dispose();
  }
}
```

## ⚡ نصائح الأداء والتحسين (Performance Tips)

:::tip البناء الصغير المصغر (Small Granular Widgets)
قسم شاشتك إلى ودجات صغيرة مستقلة. عندما تتغير حالة ودجة صغيرة، تُعاد دعوة `build()` للودجة الصغرى فقط دون إعادة رسم الصفحة بالكامل.
:::

// ❌ 1. مناداة setState داخل دالة build()
@override
Widget build(BuildContext context) {
  // 💥 خطأ كارثي: يسبب Infinite Re-build Loop!

## 🎤 أسئلة وأجوبة المقابلات (Interview Q&A)

<details>
<summary><strong>س1: ما هو الفرق الجوهري بين Widget Tree و Element Tree؟</strong></summary>

الـ **Widget Tree** هي مجرد تجميعة وصفية خفيفة الوزن (Blueprint) ثنائية الحتمية. بينما الـ **Element Tree** هي الكائنات الفعلية المدارة في الذاكرة والتي تربط بين الوصف والرسم الفعلي في الشاشة.

</details>

<summary><strong>💡 اضغط هنا لرؤية الحل النموذجي المشروح بالتعليقات (Solution Code)</strong></summary>

import 'package:flutter/material.dart';

class LifecycleDemo extends StatefulWidget {
  const LifecycleDemo({super.key});

  @override
  State<LifecycleDemo> createState() => _LifecycleDemoState();
}

class _LifecycleDemoState extends State<LifecycleDemo> {
  @override
  void initState() {
    super.initState();
    print('LifecycleDemo mounted.');
  }

  @override
  void dispose() {
    print('LifecycleDemo unmounted.');
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return const Center(child: Text('Lifecycle Demo'));
  }
}

- `initState` تُنفذ مرة واحدة، و `dispose` تُنفذ لتنظيف الذاكرة.
- الـ Element Tree هي العقل المدبر الذي يقلل من عمليات الرسم المكررة.
