# 6.1 الاختبارات الأحادية للـ ViewModels والـ Repositories (Unit Testing)

ضمان استقرار التطبيق وثبات وظائفه عند إضافة ميزات جديدة يتطلب كتابة **اختبارات أحادية (Unit Tests)**. لكون معمارية MVVM تقوم بفصل المنطق عن الواجهة، فإن كتابة Unit Tests للـ ViewModels يصبح في غاية السهولة والمباشرة.

---

## 🎯 أهداف الدرس (Learning Objectives)

1. فهم مفهوم وتأثير الاختبارات الأحادية (Unit Testing).
2. تطبيق نمط **AAA (Arrange, Act, Assert)** المعتمد عالمياً.
3. إنشاء الخدمات الوهمية لطبقة البيانات باستخدام مكتبة **`mocktail`**.
4. اختراع سيناريوهات نجاح وفشل جلب البيانات والتأكد من إخطار الواجهة بالتغيير.

---

## 📘 الشرح النظري (Theoretical Explanation)

### نمط AAA لكتابة الاختبارات:
1. **Arrange (التهيئة):** إعداد التبعيات والكائنات الوهمية وتجهيز الحالة الأولية.
2. **Act (التنفيذ):** استدعاء الدالة المراد اختبارها بالـ ViewModel.
3. **Assert (التحقق):** التأكد من أن النتيجة الحاصلة تنطبق 100% مع التوقع المطلوب (Expect).

---

## 💻 التطبيق المعماري (MVVM & Clean Code)

اختبار أحادي متكامل داخل مجلد `test/presentation/viewmodels/user_viewmodel_test.dart`.

```dart
// ==========================================
// File: test/presentation/viewmodels/user_viewmodel_test.dart
// Description: اختبار أحادي شامل لـ UserDetailsViewModel
// Architecture Layer: Unit Tests
// ==========================================

import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';

// استيراد الطبقات الحقيقية
import 'package:doc_flutter/data/models/user_model.dart';
import 'package:doc_flutter/data/repositories/user_repository_impl.dart';
import 'package:doc_flutter/presentation/viewmodels/user_details_viewmodel.dart';

// 1. إنشاء فئة وهمية للمستودع باستخدام mocktail
class MockUserRepository extends Mock implements UserRepositoryImpl {}

void main() {
  late UserDetailsViewModel viewModel;
  late MockUserRepository mockRepository;

  // يتم تنفيذها قبل كل دالة اختبار فردية
  setUp(() {
    mockRepository = MockUserRepository();
    viewModel = UserDetailsViewModel(mockRepository);
  });

  group('اختبارات UserDetailsViewModel -', () {
    const tUser = UserModel(
      id: '101',
      username: 'أحمد علي',
      email: 'ahmed@test.com',
    );

    test('يجب أن تكون الحالة الأولية isLoading مساوية لـ false', () {
      expect(viewModel.isLoading, false);
      expect(viewModel.user, null);
    });

    test('يجب أن يقوم بتحميل بيانات المستخدم بنجاح وتغيير الحالة', () async {
      // 1. Arrange: محاكاة إرجاع المستودع الوهمي للنموذج
      when(() => mockRepository.getUserById('101'))
          .thenAnswer((_) async => tUser);

      // 2. Act: استدعاء دالة جلب البيانات بالـ ViewModel
      final future = viewModel.loadUser('101');

      // التحقق من حالة التحميل المؤقتة
      expect(viewModel.isLoading, true);

      await future;

      // 3. Assert: التحقق من التغير النهائي للحالة والنموذج
      expect(viewModel.isLoading, false);
      expect(viewModel.user, tUser);
      verify(() => mockRepository.getUserById('101')).called(1);
    });
  });
}
```

<SummaryBox title="خلاصة الدرس 📌">

- تتيح معمارية MVVM اختبار كل منطق التطبيق بـ Unit Tests دون الحاجة لتشغيل محاكي الأجهزة (Emulator).

- نستخدم `mocktail` لإنشاء كائنات وهمية تطابق واجهات الـ Repositories وتمنع إجراء الاتصالات الشبكية الحقيقية أثناء الاختبار.
