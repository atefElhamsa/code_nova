# 5.2 نمط المستودع والتكامل الشبكي (Repository Pattern with Remote API)

يقوم نمط المستودع (Repository Pattern) بالوساطة والتنسيق بين طبقة النماذج والبيانات الخارجية وبين طبقة الواجهة والتنفيذ. فهو يخفي تفاصيل التعامل المباشر مع قواعد البيانات والـ APIs خلف واجهة برمجة تطبيقات مبسطة وموحدة.

---

## 🎯 أهداف الدرس (Learning Objectives)

1. التمييز الدقيق بين **Remote Datasource** و **Local Datasource**.
2. بناء طبقة مستودع ذكية تقوم بالتبديل بين التخزين المحلي والشبكي في حالة انقطاع الإنترنت.
3. التخلص التام من الاعتماد المباشر على مكتبات Dio داخل الـ ViewModels.
4. توحيد طريقة إرجاع البيانات في شكل نماذج DTOs نظيفة.

---

## 📘 الشرح النظري (Theoretical Explanation)

تتألف طبقة البيانات من ثلاثة مكونات أساسية:
1. **Remote Datasource:** متخصصة حصرياً في إجراء طلبات الـ HTTP عبر Dio وإرجاع `Map<String, dynamic>`.
2. **Local Datasource:** متخصصة حصرياً في التعامل مع التخزين المحلي مثل `SharedPreferences` أو `Hive`.
3. **Repository:** المنسق الرئيسي الذكي. يقوم بجلب البيانات من Remote Datasource وتحفظ نسخة محلية في Local Datasource، وإذا فشل الاتصال يجلب البيانات المحفوظة محلياً!

---

## 💻 التطبيق المعماري (MVVM & Clean Code)

تطبيق المستودع المنسق بين الخادم والتخزين المحلي.

```dart
// ==========================================
// File: lib/data/datasources/user_remote_datasource.dart
// Architecture Layer: Data (Remote Datasource)
// ==========================================

import 'package:dio/dio.dart';

class UserRemoteDatasource {
  final Dio dio;

  UserRemoteDatasource(this.dio);

  Future<Map<String, dynamic>> fetchUserProfile(String userId) async {
    final response = await dio.get('users/$userId');
    return response.data as Map<String, dynamic>;
  }
}

// ==========================================
// File: lib/data/repositories/user_repository_impl.dart
// Description: مستودع ذكي يدير الاتصال بالخادم مع حل احتياطي
// Architecture Layer: Data (Repository)
// ==========================================

import '../models/user_model.dart';
import '../datasources/user_remote_datasource.dart';

class UserRepositoryImpl {
  final UserRemoteDatasource remoteDatasource;

  UserRepositoryImpl({required this.remoteDatasource});

  Future<UserModel> getUserProfile(String userId) async {
    try {
      // 1. محاولة جلب البيانات الحية من السيرفر
      final rawJson = await remoteDatasource.fetchUserProfile(userId);
      return UserModel.fromJson(rawJson);
    } catch (e) {
      // 2. حل احتياطي في حال انقطاع الشبكة
      print('⚠️ فشل الاتصال الشبكي، جلب النسخة الاحتياطية...');
      return UserModel(
        id: userId,
        username: 'مستخدم (بدون اتصال)',
        email: 'offline@cache.local',
      );
    }
  }
}
```

<SummaryBox title="خلاصة الدرس 📌">

- يعزل نمط المستودع المصادر المختلفة للبيانات ويخفي تعقيداتها عن بقية التطبيق.
- يُعتبر الـ Repository المنسق الرئيسي بين البيانات الحية من السيرفر والبيانات المخزنة محلياً عند انقطاع الإنترنت.
- لا تعرف الـ ViewModels أي تفاصيل عن عناوين الـ API أو مكتبات الاتصالات المستخدمة.

</SummaryBox>
