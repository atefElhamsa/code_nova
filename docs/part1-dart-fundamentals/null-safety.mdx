# 1.2 الأمان المطلق ضد القيم الخالية (Sound Null Safety)

تُعتبر ميزة **Sound Null Safety** واحدة من أهم وأقوى الميزات في لغة Dart؛ حيث تمنع تماماً أشهر أسباب انهيار التطبيقات (Crashes) في عالم البرمجة، وهو خطأ استدعاء القيمة الخالية المشهور بـ `NullPointerException`. ستتعلم في هذا الدرس كل ما يتعلق بالتعامل مع القيم الخالية والأمان منها خطوة بخطوة.

---

## 🎯 الأهداف التعليمية

1. فهم معنى القيمة الخالية (`Null`) ولماذا تُعتبر خطيرة إذا لم يتم التعامل معها بحذر.
2. التمييز بين الأنواع القابلة للقيم الخالية (`Nullable`) وغير القابلة (`Non-Nullable`).
3. إتقان استخدام معاملات الأمان: (`?.`, `??`, `??=`, `!`, `?.[]`, `...?`).
4. فهم ميزة ترقية الأنواع التلقائية (`Type Promotion`) وكيف يوفرها مترجم Dart.
5. الإجابة بنجاح على أسئلة المقابلات الشخصية (Interview Questions) المتعلقة بهذا الموضوع.

---

## 1. ما هو مفهوم الـ Null؟

القيمة `null` تعني ببساطة "عدم وجود قيمة في هذا المتغير". تكمن المشكلة الكبرى عندما تحاول قراءة خصائص أو تنفيذ دوال على متغير لا يحمل قيمة:

```dart
// في اللغات الأخرى (مثل Java أو JS القديمة) - هذا يتسبب في كراش فور تشغيل البرنامج!
String name = null;
print(name.length); // 💥 خطأ استثناء: NullPointerException
```

**حل لغة Dart الجذري لهذه المشكلة:**
يقوم مترجم لغة Dart (Compiler) بمنع هذا الخطأ أثناء كتابة الكود (Compile Time) ولا يسمح بتمرير الكود أصلاً:

```dart
// في لغة Dart - يظهر خطأ تجميع (Compile Error) فوري لمنع الأخطاء مستقبلاً
String name = null; // ❌ خطأ: لا يمكن إسناد قيمة Null لمتغير غير قابل للقيم الخالية String
```

## 2. الأنواع غير القابلة للقيم الخالية مقابل القابلة لها (Non-Nullable vs Nullable)

في لغة Dart، **جميع أنواع البيانات غير قابلة للقيم الخالية (Non-Nullable) بشكل افتراضي**:

```dart
// ✅ Non-Nullable - مضمون دائماً وجود قيمة داخل المتغير
String  city    = 'Cairo';
int     age     = 25;
double  score   = 98.5;
bool    active  = true;

// ❌ لا يمكن إسناد null لمتغير افتراضي
String  name    = null; // خطأ تجميع!
```

أما إذا كانت البيانات قد تكون خالية بالفعل (مثل اسم الشهرة أو الخصومات)، فنضيف علامة الاستفهام `?` بعد نوع المتغير:

```dart
// ✅ Nullable - تحديد صريح بأن المتغير قد يحمل قيمة null
String? nickname;      // قد لا يكون للمستخدم اسم شهرة
int?    phoneExt;      // قد لا يوجد امتداد هاتف
double? discount;      // قد لا يوجد خصم على المنتج

print(nickname);       // يطبع null بصورة آمنة دون كراش
```

## 3. معاملات التعامل مع القيم الخالية (Null-Aware Operators)

### `?.` - Safe Access

```dart
String? email = getUserEmail(); // might return null

// ❌ Dangerous - crashes if email is null
print(email.length);

// ✅ Safe - returns null instead of crashing
print(email?.length);

// Chain safely
String? upper = email?.trim()?.toUpperCase();
```

---

### `??` - Fallback Value

```dart
String? nickname = getNickname();

// "If nickname is null, use 'Anonymous'"
String displayName = nickname ?? 'Anonymous';

// Chain multiple fallbacks
String label = nickname ?? 'Guest';

print(displayName); // Either the nickname or 'Anonymous'
```

---

### `??=` - Assign Only If Null

```dart
String? cachedResult;

// Assigns ONLY if currently null
cachedResult ??= computeExpensiveResult();
// Second call does nothing - already assigned!
cachedResult ??= computeExpensiveResult();

print(cachedResult); // result from first call
```

Equivalent to:
```dart
if (cachedResult == null) {
  cachedResult = computeExpensiveResult();
}
```

---

### `!` - Force Unwrap (Dangerous!)

```dart
String? value = 'Hello';

// You tell Dart: "I KNOW this is not null - trust me"
String result = value!;
print(result); // 'Hello'

// But if you're WRONG:
String? nothing = null;
String crash = nothing!; // 💥 Null check operator used on a null value
```

> ⚠️ استخدم `!` بس لما تكون **متأكد 100%**. في الغالب `??` أو `?.` أحسن.

---

### `?.[]` - Safe Index Access

```dart
List<String>? tags = getTags();

String? first = tags?[0]; // null if tags is null, otherwise tags[0]
int?    count = tags?.length;
```

---

### `...?` - Null-Aware Spread

```dart
List<String>? extras = getExtras(); // might be null

List<String> allItems = [
  'default',
  ...?extras,   // spreads nothing if null, spreads items if not null
  'end',
];
```

## 4. الترقية التلقائية للأنواع (Type Promotion)

يقوم مترجم لغة Dart بتتبع مسار فحص الشروط (`if-checks`) وترقية نوع المتغير تلقائياً إلى نوع غير قابل لـ null بمجرد التأكد من وجود قيمة:

```dart
String? name = getUserName();

// هنا: نوع المتغير هو String? - يحتاج استخدام ?. للوصول للخصائص
print(name?.length);

if (name != null) {
  // هنا: قام المترجم بترقية نوع المتغير إلى String تلقائياً!
  // لا داعي لاستخدام ?. أو ! بداخل هذا البلوك
  print(name.length);        // ✅ وصول مباشر وآمن
  print(name.toUpperCase()); // ✅ جميع دوال النص أصبحت متاحة
}

// بعد الخروج من شرط if: يعود المتغير لنوعه الأصلي String?
```

**نمط الحماية المبكرة (Guard Clause Pattern) - الأسلوب الاحترافي:**

```dart
String processName(String? name) {
  if (name == null) return 'Unknown'; // الخروج المبكر في حالة عدم وجود قيمة
  // بدءاً من هذه السلسلة، يتم ترقية name إلى String تلقائياً
  return name.trim().toUpperCase();   // لا حاجة لاستخدام ! إطلاقاً
}

void main() {
  print(processName(null));       // Unknown
  print(processName('  ahmed ')); // AHMED
}
```

## 5. تطبيق عملي شامل (Practical Example)

```dart
// Top-level functions only - no classes yet!

/// Returns a greeting message - null if name is blank
String? buildGreeting(String? firstName, String? lastName) {
  if (firstName == null && lastName == null) return null;

  final first = firstName?.trim() ?? '';
  final last  = lastName?.trim()  ?? '';
  final full  = '$first $last'.trim();

  return full.isEmpty ? null : 'Hello, $full!';
}

/// Safe display - always returns a non-null String
String safeDisplay(String? value, String fallback) {
  return value?.trim().isNotEmpty == true ? value!.trim() : fallback;
}

void main() {
  // Test buildGreeting
  print(buildGreeting('Ahmed', 'Ali'));    // Hello, Ahmed Ali!
  print(buildGreeting('Sara', null));      // Hello, Sara!
  print(buildGreeting(null, null));        // null

  // Test safeDisplay
  String? nickname;
  String? city = 'Cairo';

  print(safeDisplay(nickname, 'Anonymous')); // Anonymous
  print(safeDisplay(city, 'Unknown'));       // Cairo

  // Null-aware operators in action
  List<String>? languages = ['Dart', 'Flutter'];
  List<String>? extras    = null;

  List<String> allSkills = [
    ...?languages,  // spreads ['Dart', 'Flutter']
    ...?extras,     // spreads nothing (null)
    'MVVM',
  ];

  print(allSkills); // [Dart, Flutter, MVVM]
  print('Count: ${allSkills.length}'); // Count: 3
}
```

## ⚡ Performance Tips

:::tip Prefer `??` over ternary for null checks
```dart
// ❌ Verbose
String name = value != null ? value : 'default';

// ✅ Concise and same performance
String name = value ?? 'default';
```
:::

:::tip Capture mutable nullable in local variable for promotion
```dart
String? _token; // mutable - no type promotion directly

void useToken() {
  // ❌ No promotion on mutable variables
  if (_token != null) {
    doWork(_token); // still String?
  }

  // ✅ Capture in local final - gets promoted!
  final token = _token;
  if (token != null) {
    doWork(token); // String ✅
  }
}
```
:::

:::tip `whereType<T>()` to filter nulls from lists
```dart
List<String?> rawNames = ['Ahmed', null, 'Sara', null, 'Omar'];

// ✅ One-liner to remove all nulls and get List<String>
List<String> names = rawNames.whereType<String>().toList();

print(names); // [Ahmed, Sara, Omar]
```
:::

## 🎤 Interview Questions & Answers

<details>
<summary><strong>Q1: ما الفرق بين Sound Null Safety و Unsound Null Safety؟</strong></summary>

- **Sound** (Dart): الـ compiler يضمن 100% إن مفيش null وقت التشغيل لو الكود اتكمبل بنجاح.
- **Unsound** (TypeScript): ممكن يتجاوز بـ `any` أو type casting - مش ضمان كامل.

**في Dart**: لو الكود compile → مفيش NullPointerException. خالص.

</details>

<details>
<summary><strong>Q2: إيه هو Type Promotion وإيه حدوده؟</strong></summary>

Type Promotion = الـ compiler بيتتبع الـ control flow ويرقي النوع تلقائياً:

```dart
String? name = getName();
if (name != null) {
  print(name.length); // promoted to String - no ! needed
}
```

**الحدود** - Promotion مش بيشتغل مع:
1. الـ mutable class fields (لأن thread تاني ممكن يغيرها).
2. الـ variables اللي بتتغير جوه closures.

**الحل**: اعمل local final copy:
```dart
final localName = name; // copy to local
if (localName != null) { /* promoted ✅ */ }
```

</details>

<details>
<summary><strong>Q3: امتى أستخدم `!` وامتى لا؟</strong></summary>

**استخدم `!` فقط لما:**
- الـ logic يضمن إن القيمة مش null وأنت متأكد.
- بعد guard clause أو type check.

**ابعد عن `!` لو:**
- ممكن تستخدم `??` أو `?.` بدله.
- مش متأكد 100%.

```dart
// ❌ Risky
String result = getApi()!;

// ✅ Safe always
String result = getApi() ?? 'fallback';
```

</details>

<details>
<summary><strong>Q4: إيه الفرق بين `??` و `?.`؟</strong></summary>

- `??` = "لو القيمة null، استخدم القيمة البديلة دي" (returns a value).
- `?.` = "لو القيمة null، وقف هنا ورجع null" (short-circuits the chain).

```dart
String? name;

String display = name ?? 'Guest'; // 'Guest'  - ?? gives a fallback
int?   len     = name?.length;    // null     - ?. short-circuits
int    safe    = name?.length ?? 0; // 0     - combine both!
```

</details>

<details>
<summary><strong>Q5: إزاي تحذف الـ null values من list بطريقة نظيفة؟</strong></summary>

```dart
List<String?> items = ['a', null, 'b', null, 'c'];

// Option 1 - whereType (cleanest)
List<String> result1 = items.whereType<String>().toList();

// Option 2 - where + !
List<String> result2 = items.where((e) => e != null).map((e) => e!).toList();

// Option 3 - nulls to empty, then filter
List<String> result3 = items
    .map((e) => e ?? '')
    .where((e) => e.isNotEmpty)
    .toList();

// All give: [a, b, c]
```

</details>

## 🐛 Common Mistakes

```dart
// ❌ 1 - Chaining ! dangerously
String name = user!.profile!.name!; // 3 potential crashes!
// ✅
String name = user?.profile?.name ?? 'Unknown';

// ❌ 2 - Forgetting Map access is nullable
Map<String, dynamic> json = {'age': 25};
String email = json['email'];   // Error! 'email' might not exist
// ✅
String? email = json['email'] as String?;
String display = email ?? 'No email';

// ❌ 3 - Unnecessary null check on non-nullable
void greet(String name) {
  if (name != null) { /* Warning! name is never null */ }
}

// ❌ 4 - Using dynamic to escape null safety
dynamic value = getResult(); // No null safety protection!
// ✅
String? value = getResult() as String?;
```

<details>
<summary><strong>💡 اضغط هنا لرؤية الحل النموذجي المشروح بالتعليقات (Solution Code)</strong></summary>

```dart
// دالة مساعدة لترجمة البيانات القابلة للإلغاء بأمان
String describe(String? name, int? age) {
  // استخدام التعبير ?? لتوفير قيم افتراضية عند وجود null
  final safeName = name ?? 'Unknown User';
  final safeAge = age != null ? '$age years old' : 'Age not provided';
  return '$safeName, $safeAge';
}

void main() {
  // 1. تعريف المتغيرات القابلة للإلغاء (Nullable Variables)
  String? username = null;
  String? city = 'Alexandria';
  int? age = 22;
  double? discount = null;

  // 2. استخدام ?? لطباعة قيمة افتراضية للاسم
  print("User: ${username ?? 'Guest'}"); // يطبع: User: Guest

  // 3. استخدام ?. للاستدعاء الآمن ثم ?? للقيمة الافتراضية
  print("City length: ${city?.length ?? 0}"); // يطبع: City length: 10

  // 4. استخدام ??= لتعيين القيمة فقط إذا كان المتغير حالياً null
  username ??= 'Ahmed';
  print("Updated Username: $username"); // يطبع: Updated Username: Ahmed

  // 5. استدعاء دالة describe المفحوصة ضد الـ null
  print(describe(username, age)); // يطبع: Ahmed, 22 years old
  print(describe(null, null));     // يطبع: Unknown User, Age not provided

  // 6. البونص: تصفية القوائم الحاوية على null باستخدام whereType
  List<String?> rawList = ['Dart', null, 'Flutter', null, 'MVVM'];
  
  // whereType<String>() تستخرج فقط العناصر النصية غير الـ null وتضمن أمان الأنواع
  List<String> cleanList = rawList.whereType<String>().toList();
  print("Clean List: $cleanList"); // يطبع: [Dart, Flutter, MVVM]
}
```

<SummaryBox title="📌 ملخص الدرس (Summary)">

### 1. القواعد الأساسية للأمان من القيم الخالية (Null Safety):
- جميع أنواع البيانات في Dart **غير قابلة لـ `null` افتراضياً** (Non-Nullable) - مما يضمن أمان التطبيق واستقراره.
- إضافة علامة الاستفهام `?` بعد نوع المتغير (مثل `String?`) تعني صراحةً أن المتغير قد يحمل قيمة `null`.

### 2. أهم المعاملات (Operators):

| المعامل (Operator) | الوصف والاستخدام | مثال توضيحي |
|:------------------:|:----------------:|:-----------:|
| `?.` | الوصول الآمن (Safe Access) | `email?.length` |
| `??` | إسناد قيمة بديلة (Fallback) | `name ?? 'مجهول'` |
| `??=` | الإسناد في حالة الـ null فقط | `cache ??= fetchData()` |
| `!` | التفكيك الإجباري (Force Unwrap) | `value!.trim()` |
| `?.[]` | الوصول الآمن لعناصر القائمة (Safe Index) | `list?[0]` |
| `...?` | النشر الآمن للقوائم (Null Spread) | `[...?nullableList]` |

### 3. الترقية التلقائية للأنواع (Type Promotion):
عند فحص المتغير بشرط `if (x != null)`، يتيقن مترجم Dart من وجود القيمة ويرقي نوع المتغير `x` تلقائياً إلى نوع غير قابل لـ `null` داخل هذا البلوك دون الحاجة لاستخدام `!` أو `?.`.

> ⚠️ **ملاحظة:** جميع الأمثلة في هذا الدرس منفذة بداخل دالة `main()` والدوال المستقلة. سنتناول موضوع الفئات والكلاسات (Classes) بالتفصيل في **درس 1.6**.

</SummaryBox>
