# 1.4 الدوال ونطاق المتغيرات (Functions & Lexical Scope)

تُعتبر الدوال (Functions) اللبنات الأساسية لأي تطبيق في لغة Dart. وظيفة الدالة هي استقبال المدخلات (Parameters)، معالجتها عبر منطق برمجي محدد (Logic)، ومن ثم إرجاع مخرجات (Return Value) أو تنفيذ أمر محدد. في هذا الدرس، ستتعلم كيفية كتابة دوال احترافية، فهم نطاق الرؤية للمتغيرات (Scope)، وتطبيق الدوال كعناصر أولية (First-Class Functions).

---

## 🎯 أهداف الدرس (Learning Objectives)

1. **إتقان هيكل الدالة البرمجية:** تحديد نوع الإرجاع الصريح (`return type`) واستخدام `void` للعمليات الإجرائية.
2. **إتقان معاملات الدوال:** التمييز بين المعاملات المكانية (Positional)، المسماة (Named)، والافتراضية (Default Values).
3. **الدوال السهمية (Arrow Functions):** كتابة دوال التعبير الواحد (`=>`) بنظافة وتجنب الأخطاء التركيبية.
4. **فهم نطاق المتغيرات والاستغلاق (Scope & Closures):** استيعاب النطاق اللفظي (`Lexical Scope`) وكيفية حجز المتغيرات عبر الـ `Closures`.
5. **الدوال كعناصر درجة أولى (First-Class Functions):** تمرير الدوال كمعاملات (`Callbacks`) وتصميم الأنماط باستخدام `typedef`.

## 💻 الكود البرمجي أولاً (Code Example First)

<span className="code-first-badge">⚡ Pure English Dart Code (Clean Architecture & Callbacks)</span>

```dart
// ==========================================
// File: lib/core/utils/shipping_calculator.dart
// Description: Pure functions showcasing named/positional parameters,
// arrow syntax, closures, and first-class function callbacks.
// Architecture Layer: Core Utils
// ==========================================

/// Type definition for order status notifications callback
typedef OnStatusChanged = void Function(String message);

/// 1. Arrow Function for VAT Calculation (Single-line expression)
double calculateVat(double price) => price * 0.14;

/// 2. Function with Positional and Named Parameters
double calculateShippingFee(
  double weightKg, {
  required bool isExpress,
  double discountRate = 0.0,
}) {
  final baseFee = isExpress ? weightKg * 20.0 : weightKg * 10.0;
  return baseFee * (1.0 - discountRate);
}

/// 3. Higher-Order Function accepting a Callback and returning a Closure
OnStatusChanged createStatusNotifier(String prefix) {
  // Lexical Closure capturing 'prefix' variable in context
  return (String message) {
    print('[$prefix] $message');
  };
}

/// 4. Main Processing Function bringing all concepts together
double calculateOrderTotal({
  required double itemPrice,
  required double weightKg,
  required bool isExpress,
  OnStatusChanged? onLog,
}) {
  final vat = calculateVat(itemPrice);
  final shipping = calculateShippingFee(weightKg, isExpress: isExpress);
  final total = itemPrice + vat + shipping;

  onLog?.call('Calculated Total: $total (Item: $itemPrice, VAT: $vat, Shipping: $shipping)');
  return total;
}
```

## 📘 الشرح التفصيلي للكود (Line-by-Line Technical Explanation)

### 1. تعريف الأنماط للدوال (`typedef`)
* **`typedef OnStatusChanged = void Function(String message);`**: نستخدم `typedef` لإنشاء اسم مستعار نقي لتوقيع الدالة (Function Signature). يسهل هذا تمرير الدالة كـ Callback في معمارية Clean Code ويزيد من مقروئية الأكواد.

### 2. الدوال السهمية (`Arrow Functions`)
* **`double calculateVat(double price) => price * 0.14;`**: رمز السهم `=>` يعوض عن الأقواس مع المعامل المباشر للإرجاع (`return`). تُستخدم فقط عندما تتكون الدالة من سطر تعبيري واحد (Expression).

### 3. المعاملات المكانية والمسماة (`Parameters`)
* **`calculateShippingFee(double weightKg, {required bool isExpress, ...})`**:
  * **`weightKg`**: معامل مكاني (Positional) يفرض تمرير القيمة في المرتبة الأولى.
  * **`{required bool isExpress}`**: معامل مسمى إجباري (Required Named Parameter)، يجب تحديد اسمه صراحة عند الاستدعاء (`isExpress: true`).
  * **`double discountRate = 0.0`**: معامل مسمى اختياري مع قيمة افتراضية.

### 4. الاستغلاق اللفظي (`Lexical Closures`)
* **`createStatusNotifier(String prefix)`**: تُرجع دالة مجهولة الاسم (Anonymous Function). تحتفظ هذه الدالة بقيمة `prefix` حتى بعد انتهاء تنفيذ الدالة الأصلية `createStatusNotifier`. هذا ما يُسمى بالـ Closure.

## 📖 الشرح المفهومي للخصائص (Concept Deep Dive)

### 1. أنواع المعاملات في Dart (Function Parameters)

تنقسم المعاملات في Dart إلى قسمين رئيسيين:

#### أ. المعاملات المكانية (Positional Parameters)
يعتمد استدعاؤها على ترتيب وضع القيمة عند الاستدعاء:
```dart
void setCoordinates(double x, double y) { ... }
// الترتيب إجباري: x ثم y
setCoordinates(10.5, 20.0);
```

#### ب. المعاملات المسماة (Named Parameters) - الأهم في Flutter!
تُوضع المعاملات بين أقواس معقوفة `{}`. تُسند القيم باسم المعامل وليس بترتيبه، مما يرفع مقروئية الكود بشكل استثنائي (Self-documenting Code):
```dart
void createUserAccount({required String username, required String email, int age = 18}) { ... }

// الاستدعاء يتم بالاسم والترتيب غير مهم
createUserAccount(
  email: 'user@example.com',
  username: 'ahmed_dev',
);
```

---

### 2. نطاق المتغيرات والاستغلاق (Lexical Scope & Closures)

#### النطاق اللفظي (Lexical Scope)
في Dart، يتحدد نطاق رؤية المتغير بمكانه في الكود الهيكلي (بين الأقواس المعقوفة `{}`). الأكواد الموجودة داخل النطاق الداخلي يمكنها قراءة متغيرات النطاق الخارجي، بينما العكس غير ممكن إطلاقاً.

```dart
bool topLevel = true; // نطاق عالمي

void main() {
  bool insideMain = true;

  if (topLevel) {
    bool insideIf = true;
    print(topLevel);   // ✅ متاح
    print(insideMain); // ✅ متاح
    print(insideIf);   // ✅ متاح
  }

  // print(insideIf); // ❌ خطأ تجميع: المتغير غير معرف في هذا النطاق!
}
```

#### الاستغلاق اللفظي (Lexical Closure)
الـ **Closure** هو كائن دالة يمتلك إمكانية الوصول إلى المتغيرات في نطاقها اللفظي الأصلي، حتى عند استدعاء الدالة خارج ذلك النطاق.

## ⚡ نصائح الأداء والتحسين (Performance Tips)

:::tip استخدام الـ Tear-offs لنظافة وسرعة الكود
عند تمرير دالة موجودة بالفعل كـ Callback، استخدم الـ Tear-off مباشرة بدلاً من كتابة دالة مجهولة مكررة:
```dart
void printItem(String item) => print(item);
List<String> items = ['A', 'B', 'C'];

// ❌ طريقة مكررة (Verbose)
items.forEach((item) => printItem(item));

// ✅ طريقة نظيفة وأسرع في التنفيذ (Tear-off)
items.forEach(printItem); 
```
:::

:::tip تجنب العمليات المعقدة داخل Callbacks الواجهة
في إطار عمل Flutter، تجنب تنفيذ حسابات رياضية معقدة أو عمليات معالجة نصوص ضخمة داخل الـ Callbacks المباشرة للبطاقات والأزرار (مثل `onPressed`) حتى لا تتسبب في تجميد الإطارات (UI Lag).
:::

## 🐛 أخطاء شائعة يجب تجنبها (Common Mistakes)

```dart
// ❌ 1. إهمال كتابة نوع الإرجاع الصريح
processData() { // 💥 عدم تحديد النوع يجعله dynamic ويفقدك أمان المترجم!
  print('Processing');
}

// ✅ الحل الصحيح: تحديد void أو النوع المرتجع صراحة
void processData() {
  print('Processing');
}


// ❌ 2. حشو أقواس المجموعة {} داخل الدالة السهمية =>
int getFive() => { return 5; }; // 💥 خطأ تجميعي! الـ => تعني return تلقائياً

// ✅ الحل الصحيح للـ Arrow Function
int getFive() => 5;


// ❌ 3. استخدام معاملات بولينية متعددة بدون أسماء (غموض الاستدعاء)
void saveUser(String name, bool isActive, bool isAdmin) {}
saveUser('Ahmed', true, false); // 💥 مبهجة! ما الذي يعنيه true و false؟

// ✅ الحل الصحيح: استخدام Named Parameters للتوضيح
void saveUser(String name, {required bool isActive, required bool isAdmin}) {}
saveUser('Ahmed', isActive: true, isAdmin: false); // ✅ واضح ونظيف جداً
```

## 🎤 أسئلة وأجوبة المقابلات الشخصية (Interview Q&A)

<details>
<summary><strong>س1: ما الفرق بين Positional Parameters و Named Parameters ومتى نستخدم كل منهما؟</strong></summary>

- **Positional Parameters:** تعتمد على ترتيب التمرير. نستخدمها عندما تكون المعاملات قليلة (1-2) ومعناها بليغ وواضح جداً من اسم الدالة (مثل `add(1, 2)`).
- **Named Parameters:** تعتمد على الاسم عند التمرير. نستخدمها عند كثرة المعاملات، أو عند وجود عدة قيم من نفس النوع (مثل القيم البولينية)، لتوفير وضوح تام وقت الاستدعاء دون الحاجة لقراءة توقيع الدالة. تُستخدم في 90% من عناصر واجهات Flutter Widgets.

</details>

<details>
<summary><strong>س2: ما هي الـ Higher-Order Functions وما علاقتها بمفهوم First-Class Functions؟</strong></summary>

لغة Dart تعامل الدوال كـ **First-Class Citizens**، مما يعني إمكانية تخزين الدالة في متغير، تمريرها كمعامل، أو إرجاعها من دالة أخرى. والدالة التي تستقبل دالة أخرى كمعامل أو ترجع دالة تُسمى **Higher-Order Function** (مثل دالة `map` و `where` في القوائم).

</details>

<details>
<summary><strong>س3: ما هو المفهوم العلمي للـ Lexical Closure في Dart؟</strong></summary>

الـ **Closure** هو كائن دالة يحتفظ برابط وحجز لمتغيرات النطاق اللفظي الذي أُنشئت فيه (Lexical Scope)، حتى بعد انتهاء تنفيذ النطاق الخارجي وخروجه من الـ Stack.

</details>

<details>
<summary><strong>س4: ما هو الـ Tear-off وكيف يرفع كفاءة ومقروئية الكود؟</strong></summary>

الـ **Tear-off** هو استخدام اسم الدالة مباشرة كـ Callback بدون لفها في دالة مجهولة جديدة (مثل تمرير `print` مباشرة لـ `forEach(print)`). يقلل الـ Tear-off من إنشاء كائنات الدوال المؤقتة في الذاكرة ويرفع سرعة التنفيذ ومقروئية الكود.

</details>

3. أنشئ دالة `calculateTotalOrder` تستقبل السعر والوزن وخيار الشحن السريع، وتستدعي الدوال السابقة لإرجاع الإجمالي: (السعر + الضريبة + الشحن).

<details>
<summary><strong>💡 اضغط هنا لرؤية الحل النموذجي المشروح بالتعليقات (Solution Code)</strong></summary>

```dart
// 1. دالة سهمية لحساب الضريبة 14%
double calculateVat(double price) => price * 0.14;

// 2. دالة الشحن بمعامل مكاني (weightKg) ومعامل مسمى إجباري (isExpress)
double calculateShippingFee(double weightKg, {required bool isExpress}) {
  // استخدام التعبير الثلاثي لتحديد السعر لكل كيلو
  return isExpress ? weightKg * 20.0 : weightKg * 10.0;
}

// 3. دالة حساب الإجمالي واستدعاء الدوال السابقة
double calculateTotalOrder({
  required double price,
  required double weightKg,
  required bool isExpress,
  void Function(String)? onLog, // 4. معامل Callback اختياري للطباعة
}) {
  final vat = calculateVat(price);
  final shipping = calculateShippingFee(weightKg, isExpress: isExpress);
  final total = price + vat + shipping;

  // استدعاء دالة الطباعة بالنمط الآمن عند وجودها
  onLog?.call('Bill Details -> Base: \$$price | VAT: \$$vat | Shipping: \$$shipping | TOTAL: \$$total');
  
  return total;
}

void main() {
  // اختبار استدعاء الدالة مع تمرير دالة print كـ Callback
  final finalPrice = calculateTotalOrder(
    price: 100.0,
    weightKg: 2.5,
    isExpress: true,
    onLog: (logMessage) => print('LOG: $logMessage'),
  );
  
  print('Final Paid Amount: \$$finalPrice');
}
```

<SummaryBox title="ملخص الدرس 📌">

- **نوع الإرجاع (Return Type):** حدد دائماً نوع القيمة المرجعة صراحة، أو `void` للعمليات التي لا ترجع قيمة.
- **الدوال السهمية (`=>`):** مخصصة للتعبيرات المباشرة المكونة من سطر واحد فقط.
- **المعاملات المسماة (`{required Type name}`):** هي الخيار المعياري والأفضل لمقروءة الأكواد في Flutter.
- **الاستغلاق اللفظي (Closures):** يسمح للدوال بالاحتفاظ بمتغيرات نطاقها الأصلي وإعادة استخدامها.
- **الـ Tear-offs:** تُحسن الأداء ومقروءة الأكواد عند تمرير الدوال كـ Callbacks.

</SummaryBox>
