# 3.1 التسميات النظيفة والمعايير الاحترافية (Clean Naming)

قراءة الكود هي العملية الأطول في تطوير البرمجيات. اتباع قواعد التسمية النظيفة يجعل الكود شارحاً لنفسه (Self-Documenting Code).

---

##  أهداف الدرس (Learning Objectives)

1. اتّباع camelCase و PascalCase بحسب المعايير.
2. تجنب الاختصارات المبهمة الأسماء.
3. تسمية الدوال كأفعال والبيانات كأسماء.

---

## 1. قواعد التسمية القياسية في Dart

### 📘 الشرح النظري
تستخدم الفئات والـ Enums نمط `PascalCase` بينما تُكتب المتغيرات والدوال والملفات بنمط `camelCase` و `snake_case`.

### 💻 التطبيق العملي
```dart
// PascalCase للفئات
class UserProfileModel {}

// camelCase للمتغيرات والدوال
double accountBalance = 150.0;

void calculateDiscountAmount() {}
```

---

## 2. الوضوح وتجنب الغموض (Self-Documenting Code)

### 📘 الشرح النظري
تجنب الاختصارات الحرفية مثل `usr` أو `p`. اسم المتغير يجب أن يعبر بدقة عن قيمته دون الحاجة لقراءة الكود المحيط.

### 💻 التطبيق العملي
```dart
// ❌ مبهم: double d;
// ✅ واضح ومباشر:
double discountPercentage = 0.15;
```

---

##  نصائح الأداء والتحسين (Performance Tips)

:::tip اسم واضح يغني عن التعليقات الزائدة
اسم المتغير البليغ يقضي على الحاجة لكتابة تعليقات شرح بديهية مكررة.
:::

---

##  أخطاء شائعة يجب تجنبها (Common Mistakes)

```dart
// ❌ 1. استخدام اختصارات غير معروفة للمتغيرات
var u = getUser();

// ✅ الحل الصحيح
var activeUser = getUser();

```
