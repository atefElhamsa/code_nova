# 7.2 إدارة الحالة والأحداث (State & Events)

بعد أن أصبح الهيكل جاهزاً، حان الوقت لنفخ الروح في تطبيقنا. في هذا الدرس، سنتعلم كيف نقوم بتخزين المهام، وكيف نلتقط ضغطة زر الإضافة لرسم مهام جديدة على الشاشة ديناميكياً باستخدام الـ DOM.

---

##  الأهداف التعليمية

1. استخدام المصفوفات لتخزين حالة التطبيق (State).
2. التقاط الأحداث (Events) ومعالجة مدخلات المستخدم.
3. إضافة عناصر HTML جديدة للـ DOM ديناميكياً.
4. ربط المنطق الداخلي (State) بواجهة المستخدم (UI).

---

## 1. إدارة الحالة (State)

التطبيق يحتاج لمكان (ذاكرة مؤقتة) يحفظ فيه المهام التي يكتبها المستخدم للتعامل معها. سنستخدم مصفوفة (Array) بسيطة.

```javascript
// مصفوفة فارغة لحفظ المهام الحالية
// استخدمنا let لأننا سنقوم بتعديلها لاحقاً
let tasks = [];
```

> 💡 **مقارنة بـ Dart:**
> هذا يماثل تعريف متغير `List<Map<String, dynamic>> tasks = [];` في كلاس الـ State في Flutter لتخزين قائمة البيانات!

---

## 2. وظيفة الإضافة والـ Event Listener

سنقوم بكتابة مستمع للحدث (Event Listener) يعمل عندما يضغط المستخدم على زر الإضافة (Add). وظيفتنا:
1. قراءة النص من الحقل.
2. تكوين كائن (Object) يمثل هذه المهمة.
3. حفظها في المصفوفة `tasks`.
4. إعادة رسم الواجهة (Render).

```javascript
addBtn.addEventListener('click', () => {
  // قراءة النص وإزالة المسافات الفارغة من الجوانب
  const taskText = taskInput.value.trim();

  // التحقق من أن النص غير فارغ (كي لا يضيف مهام وهمية)
  if (taskText !== "") {
    
    // 1. إنشاء كائن للمهمة الجديدة
    const newTask = {
      id: Date.now(), // نستخدم التاريخ الحالي بالملي ثانية للحصول على ID فريد لا يتكرر!
      text: taskText,
      completed: false // افتراضياً المهمة الجديدة غير مكتملة
    };

    // 2. إضافتها لحالة التطبيق (State)
    tasks.push(newTask);

    // 3. مسح حقل الإدخال ليتمكن المستخدم من كتابة مهمة أخرى فوراً
    taskInput.value = "";

    // 4. تحديث واجهة المستخدم (سنكتب هذه الدالة في الخطوة القادمة)
    renderTasks();
  }
});
```

---

## 3. تحديث واجهة المستخدم (Render)

نحتاج دالة لتقوم بمسح القائمة الحالية من الشاشة ورسمها بالكامل من جديد بناءً على محتوى المصفوفة الحديثة (هذا هو أساس عمل React و Flutter).

```javascript
function renderTasks() {
  // تفريغ القائمة من الـ HTML أولاً لتجنب التكرار
  taskList.innerHTML = "";

  // المرور على مصفوفة المهام عنصراً عنصراً
  tasks.forEach((task) => {
    // إنشاء عنصر قائمة (li) جديد لكل مهمة
    const li = document.createElement("li");
    
    // إذا كانت مكتملة، أضف الكلاس الخاص بالتخطي (strike-through)
    if (task.completed) {
      li.classList.add("completed");
    }

    // تجهيز محتوى الـ li (اسم المهمة + زر الحذف) باستخدام Template Literals
    // نستخدم onClick بداخل الـ HTML لاستدعاء دوال التعديل والحذف
    li.innerHTML = `
      <span class="task-text" onclick="toggleTask(${task.id})">${task.text}</span>
      <button class="delete-btn" onclick="deleteTask(${task.id})">Delete</button>
    `;

    // إلحاق (لصق) الـ li بداخل الـ ul الموجودة في الصفحة
    taskList.appendChild(li);
  });
}
```

## 4. الإكمال والحذف (Toggle & Delete)

في الـ HTML الذي تم إنشاؤه أعلاه، استدعينا دوال `toggleTask` و `deleteTask`. لنقم بكتابتها للتحكم في حالة المصفوفة.

```javascript
// تبديل حالة الاكتمال بناءً على الـ ID
function toggleTask(id) {
  // نقوم بتحديث المصفوفة: نبحث عن المهمة المطلوبة ونعكس حالتها
  tasks = tasks.map(task => {
    if (task.id === id) {
      return { ...task, completed: !task.completed }; // عكس الحالة (true->false / false->true)
    }
    return task;
  });
  
  renderTasks(); // أمر الشاشة بإعادة الرسم للحالة الجديدة
}

// حذف المهمة بناءً على الـ ID
function deleteTask(id) {
  // التصفية: سنُبقي جميع المهام ما عدا المهمة التي تملك هذا الـ ID
  tasks = tasks.filter(task => task.id !== id);
  
  renderTasks(); // إعادة الرسم بعد الحذف
}
```

---

## ⚡ Performance Notes

:::tip استخدام `DocumentFragment` للأداء القوي
في هذا التطبيق الصغير، استخدام `appendChild` بداخل حلقة التكرار `forEach` يعمل بشكل ممتاز. ولكن، إذا كان لديك 10 آلاف مهمة، فهذا يعني أنك تحدث الـ DOM وتجبره على إعادة رسم الشاشة 10 آلاف مرة! للمشاريع العملاقة، نستخدم كائناً وسيطاً يسمى `DocumentFragment`، نضع فيه كل العناصر، ثم نضيف هذا الـ Fragment للـ DOM دفعة واحدة (عملية رسم واحدة فقط). 
:::

## Interview Questions & Answers

<details>
<summary><strong>Q1: لماذا نستخدم `Date.now()` كـ ID للمهمة بدلاً من ترتيبها (Index)؟</strong></summary>

الاعتماد على رقم الترتيب (مثل 0, 1, 2) كـ ID فكرة سيئة جداً عند الحذف. إذا حذفت العنصر 0، فإن العنصر 1 سيصبح هو 0، وسيتغير الـ ID الخاص به وتختلط الأمور. استخدام `Date.now()` يولد رقماً فريداً مستقلاً تماماً (اللحظة الزمنية الحالية بالملي ثانية) ولن يتكرر أبداً ولا يتأثر بترتيب العنصر!
</details>
